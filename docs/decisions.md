# 决策记录

已经定下的事，后续开发不再重开。

1. **方案**：词库 + 语言模型 + 本机学习。纯模型生成候选的路线试过（2026-10-08 至 10-12），第一层做不到，放弃。
2. **四个层次的优先级**：一、输入正确（词优先）；二、速度；三、联想（已去掉）；四、学习。上一层不降，下一层才算。
3. **不联网**。沙盒内，没有网络权限，也不会申请。
4. **学习是真正的学习**：微调模型，训练前后校验，变差回滚。不记录选择次数来排序。
5. **不写死规则**。不为具体词、具体场景加特例；一般性的输入惯例（数字后的 . 和 : 保持英文、引号开闭）可以。
6. **标准答案按大众用法**：装机版的候选顺序以大众文本为准；个人偏好只通过本机学习体现。
7. **输入法是打词的工具**：主测试是“在真实前文下打一个词”的首选率，不是整句。
8. **单字母不是单词**；同时有英文和中文候选时中文优先。中文候选指词库里的一个词：几个单字或几个词拼在英文字母上的读法不算（2026-10-19，loading 有前文时被“咯啊定”顶掉）。
9. **联想与预测去掉**（2026-10-16）：键盘上读联想的成本高于省下的字母，实测停顿点命中 15.8%、每次省 0.21 字；标点预测也去掉。候选只来自拼音。
10. **标点直接出中文符号，没有选择面板**（2026-10-20）：中文模式下标点键直接出中文符号（和系统拼音一样），要英文符号切到英文模式；数字后的 . 和 : 保持英文、引号成对照旧。原来的做法是符号先上屏、面板里再换成英文符号或别的写法：换的时候要应用报告并替换光标前的文字，终端不支持（面板一出来就被关掉，Tab、方向键都换不了）；面板开着时数字和方向键改了意思（$100 少一个 1），还有 2 秒的计时。2026-10-18 试过的“正在输入”方式在浏览器、终端里回车要按两次。所以整个面板去掉。
11. **中英文切换用单独按 Shift，Caps Lock 是大写锁定**（2026-10-20 改）：和其他第三方输入法一样，Caps Lock 亮时字母直接大写上屏、不拼音，不切换中英文；切换键在设置的快捷键里可改（也可以把 Caps Lock 加回去，亮=英文）。原来默认 Caps Lock 也切换、亮着时打小写，灯和打出的字对不上。旧设置里的 Caps Lock 升级后去掉一次，切换键因此一个不剩时恢复左右 Shift。
12. **快捷键设置是录键**，不是选项；普通键必须带 ⌘⌃⌥（F 键除外）。
13. **学习后打字回 NPU**：学到的参数写回 Core ML 模型副本；训练留在 GPU；打字时训练暂停。
14. **模型结构保持 8 层**：16 层的 lm9x 词测试只高 0.1 到 0.3，回放低 1.5，包大 160 MB，学习慢一倍，不采用。2026-10-22 起出厂模型是 clean2（同样结构，清洗后的数据），见第 25 条。
15. **每个例子代表一类问题**，先想清楚类别再改；改一处、测全部、不降才装机。
19. **键盘拼音按 GF 3006-2001《汉语拼音方案的通用键盘表示规范》**（2026-10-20）：字母、声母、韵母直接敲；ü 能省两点的敲 u，不能省的敲 v（lv、nve）；隔音符号敲 '，打字时照原样显示，原样上屏时保留（xi'an）；ê 敲 ea（欸，词库里给 pypinyin 读 ê 的字加上读音 ea，其余行不变）。声调数字（4.4，guo2jia1）不支持：拼音后的数字用来选候选，和系统拼音一样。
25. **训练数据和测试数据都用清洗后的版本，出厂模型换成 clean2**（2026-10-22，用户：“我更需要一个清洗后的数据版本”“需要测试数据也是清洗后的版本”）：
    - **数据**：训练文本和留出文本按同一套规则清洗（`Training/cleaning.py`：去掉个人信息和不是打出来的行）。验证集和所有测试集的上文也都是清洗后的，目标句不受影响。
    - **训练**：clean2 是 lm9 的三段做法在清洗后的数据上从头训出来的（`Training/train_base.sh`）。
    - **怎么判定**：旧句子集偏向 lm9：引擎参数在上面调过，lm9 也是在上面挑出来的，句子还有不少原样出现在训练数据里。所以另做了新测试集（`Data/fresh/`，`Tools/make_fresh_eval.py`）：清洗后的留出文本，训练数据里一条都没有，不用来调任何东西，只用来判定。
    - **结果**：新测试集上 clean2 与 lm9 打平（新错 66、新对 62，p = 0.79），只有论坛 18 比 5 待观察。学习检查集也换成新的 456 句对话（旧检查集就是旧对话句子集），clean2 的学习测试以 6e-5 采纳。
    - **门槛**：旧句子集上 clean2 低 0.3 到 3.3，只作防退步参考，判定看新测试集。
24. **GPU 上的模型权重不做成常量**（2026-10-22）：系统的诊断报告里，输入法每 1–8 小时就超过一次磁盘写入限额（24 小时 2 GB），从 0.1 版起一直如此，没有崩溃。原因是 MPSGraph 会把图里每个常量的数据写到磁盘，建图、编译、第一次运行各写一遍；一次学习要建 4–5 个图，每次约 360 MB。评分模型和训练器的权重改为从 GPU 缓冲区喂入，算出的分数与改前逐位相同，学习结果不变；一次学习会话的写入从 359 MB 降到 26 MB（只剩学到的参数文件）。保留学习结果时 Core ML 加载新副本还要写约 79 MB 编译缓存，这是系统的做法，仍保留：打字走 NPU。
23. **双拼、候选框里删学错的词**（2026-10-21）：设置“输入方式”一组：“使用双拼”开关（默认关）和“双拼方案”选择；方案一直显示，开关关着时变灰不能选，打开时用选好的方案，留常用的 4 种：小鹤（打开时默认）、自然码、微软、搜狗（智能ABC、紫光、拼音加加、中文之星、国标用的人少，按用户意见去掉；搜狗双拼系统输入法、搜狗、微信、雾凇拼音都有，按雾凇拼音的定义加上，它和微软只差 ve 只在 t 上）。双拼的两个键先换成全拼音节（小鹤 nihc → ni'hao）再交给原来的引擎，候选的长度再换回按键数，所以词库、模型、学习、模糊音都照用；输入框显示全拼（ni hao），学习按全拼记。按键表以各方案的公开定义为准，对照了 fcitx5 的 libime 和鼠须管的雾凇拼音配置（两边一致；微软、搜狗的零声母两种打法都收：o 加韵母键，a、e 开头的用首字母加韵母键，如 an 打 aj）；零声母按各方案自己的写法（o 引导，或单字母双写、双字母照写、三字母首字母加韵母键）。两个音节落在同一对键上时取字多的那个（lo 是 luo：罗 落 洛 …，咯 也读 luo），所以双拼打不出的只有 lo 的“囖”和 ê（欸，各方案都没有定义）。微软、搜狗的 ing 在 ; 键上，打拼音时 ; 跟在还没配韵母的声母键后面是韵母键。日期、时间、星期、农历和符号这些插在名称后面的结果不记进学习（星期二明天就不对了）。对话句集双拼和全拼的选率完全一样（12.10%），新闻 8.49% 对 8.24%；每字击键 3.03–3.25 → 2.18。Shift+Delete：打拼音时选中一个候选按 Shift+Delete，撤销学到的这个词（和设置里点标签一样），候选随即重排。
22. **快捷输入**（2026-10-20）：v 加数字出中文和大写（v1234.5 → 一千二百三十四点五、壹仟贰佰叁拾肆点伍、壹仟贰佰叁拾肆元伍角、1,234.5），v 加算式出结果（v12*3+5 → 41、12*3+5=41，有 + - * / ^ % 和括号），vu 加 4–6 位十六进制出字符（vu4e00 → 一）；拼音音节不以 v 开头，所以只有 v 后面紧跟数字或符号时数字和符号才进入输入、不选候选（video、vue 照旧是英文）。日期、时间、星期、农历四个词后面跟当时的值（riqi → 日期 2026-10-20 …，nongli → 农历 丙午年九月十一），排在名称之后，和打名称出符号一样（Engine/QuickInput.swift）。快捷输入的结果不记进学习。
21. **模糊音、以词定字**（2026-10-20，对照 Rime、fcitx5 补上）：模糊音在设置里逐条勾选，默认全关（和系统拼音一样），一条就是一对音，共 12 条，一行 4 条对齐排：z=zh、c=ch、s=sh、n=l、l=r、f=h、an=ang（只管 lan/lang 这类，不连带 ian、uan）、ian=iang、uan=uang、en=eng、in=ing（这 11 条和搜狗官方列的一样），u=ü（nu 出 女、lu 出 绿，小企鹅 fcitx5 有这一条；2026-10-21 加），改了下一个键就生效。lue、nue 不算模糊音，不用设置就读作 lüe、nüe（略、虐，zhanlue → 战略），和 Rime 默认一样；之前只认 lve、nve，lue 出“卤鹅”。模糊读法每个音节扣 1（比打错键的 2.5 起小）。全部打开时，标准拼写的词测试降 0.5–0.8、句子集降 2–4.7（新闻），所以只建议开自己需要的。以词定字：打拼音时 [ 上屏高亮词的第一个字、] 上屏最后一个字（bianji → 编 / 辑），只对两个字以上的中文词；单字、英文和不在打拼音时，[ ] 照旧出【】。这样挑出的字不记进学习（拼音拼的是整个词）。
20. **对照 GB/T 19246-2003《信息技术 通用键盘汉字输入通用要求》**（2026-10-20）：标点按系统拼音的习惯：` → ·、{ } → 「」、| → ｜；标准表 1 里另有的写法（．、［］、〔〕、〈〉、连接号 — －）按键不加（用户 2026-10-20：“按系统习惯就可以了”），改为打名称出符号：50 个两音节以上的名称（引号、括号、书名号、省略号、百分号、摄氏度、箭头、对号、星号、人民币等）对应 75 个符号，放在词库单独的 symbols 表里，排序完成后插在名称这个词的后面（yinhao：引号 「」 『』），所以符号永远不会是第一个；一开始把符号当作词放进词库，有前文时模型偏爱标点，把“，”排到了“逗号”前面，所以改成这样。词库里没有的名称（六角括号、方头括号、波浪号、除号）作为词加入，编号排在原有词之后（二元模型不用重算）；单音节的名称（du → °）不加，免得挤进常用字的候选。字符集（4.2）：pypinyin 有读音的汉字都能打（41,849 个，基本区 20,923 个），新加的字只取《汉语拼音方案》里已有的音节（方言音 din、wong 和叹词 m、ng 不加），频率在最低一档，放在单独的 rare_characters 表里：放进主表时每次按前缀、首字母查词都要多扫几万行，打字慢 5–25%（同机交替对比），单独放后主表与原来逐行相同、速度回到原来的水平；整段输入是一个音节时列出这个音节的全部字（主表加 rare_characters），翻页可到。这台机器上没有字体能显示的字不列（显示成方框没有用）：扩展 B 区以后的字在输入法里用系统的字体回退逐个查、记住结果（不同 macOS 版本字体不同，所以不在建库时筛）；macOS 27 上扩展 B–F 的 14,687 个只有 929 个能显示，基本区和扩展 A 区全部能显示。读音（4.3.3）对照 1985 年《普通话异读词审音表》：585 个统读字的规定读音词库里都有，按词规定读音的 633 个词全部一致，只有 12 个文言词沿用旧读（仆射 pu ye、期年 ji nian、法家拂士 bi 等）。性能（4.4）见 benchmarks.md。
18. **学习的检验按本人判断，学习率提高**（2026-10-18）：查出学习弱的根本原因是学习率太小（2e-5，本人和三个论坛作者都一样，模型连训练过的话都记不住）。学习率改为 6e-5，检验不过时用 2e-5 重训一次。单独敲词的检验改为本人最近的输入（大众常用词一项只记录不拦截：单独敲词时只有本人打过的词会动，它量到的全是本人的个人化）；大众句子仍不许降超过 1 个点。句子中间的学习提升规则删掉（学习率提高后模型自己就做到同样的效果）；单独敲词的保护（只往上提）保留，根子在出厂模型单独认词弱。
17. **英文词补全、写法按用法定**（2026-10-18）：英文词表取满 5 万词的词频表（只取前 3 万时漏了 dialog 这类常用词）；普通英文词默认小写，只有某种写法在中文文本里占 60% 以上才排第一（OK），占 20% 以上的其他写法作为后面的候选（hello 之后有 Hello），刻意的大小写混写照旧（iPhone、macOS）。原来每个词只给中文文本里最常见的一种写法，常用词里约三成被定成了大写（IT、Hello、School）。英文词测试 30.17% → 32.83%，中文词库逐行不变。
16. **安装包瘦身只做无损的**（2026-10-16）：出厂权重从 Core ML 模型文件里读（去掉 57 MB 的重复拷贝）；词库去掉不读的列和索引并压实（151 → 109 MB）；二元模型改为按行存储、概率用 16 位对数（189 → 98 MB），词对不剪枝：剪到出现 ≥10 次会让对话句集降 0.7、输入法真实语料降 2.3 个点。
